# chat-with-books

Farsi Q&A over a fixed Book set through Cognee. The whole memory layer stays on Postgres (ADR-0001). Chat runs on `glm-5.3-flash` through **AvalAI** at `https://api.avalai.ir/v1` (moved from Z.AI's GLM Coding Plan on 2026-09-13 — the coding-plan weekly quota was exhausted, error 1310, reset 2026-09-15 17:06; ADR-0002's Z.AI routing resumes by flipping `LLM_ENDPOINT` back in compose). Embeddings stay on AvalAI at `https://api.avalai.ir/v1` (ADR-0002).

The Book set is two Books: طرح کلی اندیشۀ اسلامی در قرآن (`tarhe-kolli.pdf`) and انسان ۲۵۰ ساله (`70143-336.pdf`). Keep both at the repo root. They are not committed.

## Session UI

A Farsi-first sheet for the whole answer pipeline — it shows the three phases in separate switchable sections (below). It proxies `recall()` to Cognee on this machine and runs Research Mode against the second Cognee service; it is not Cognee `--profile ui`.

```powershell
powershell -ExecutionPolicy Bypass -File start-ui.ps1
```

`start-ui.ps1` reads `LLM_API_KEY` from `.env` into the process env — `serve.py` takes the key from the host env, never from `.env` (that file is compose-only) — then runs `python ui/serve.py`. Without the key neither the Quote-selection picker nor the phase-2 composer can run: the picker's empty reply falls back to the streamed prose with its recorded note, and the composer's empty blocks land nothing in phase 2's tab — phase 1's answer stands either way. The Evidence pool is never rendered as a fallback.

The same sheet also runs as a container, under the `session` profile:

```powershell
docker compose --profile session up -d --build
```

It builds from `ui/Dockerfile` (a stdlib-only image: the base interpreter plus `serve.py` and `index.html`, nothing installed), talks to `http://cognee:8000` and `http://cognee-next-tier:8000` by container-network name — next-tier's `8001` is only the host publish — and lifts `LLM_API_KEY` by compose interpolation from the compose-only `.env`, so the key never enters the image. The phone-gate quota and the research sessions live in the `session_quota` volume at `/data/usage.sqlite3` and `/data/research.sqlite3`; when switching from the host process, carry the counts over once with `docker cp ui/usage.sqlite3 chat-with-books-session:/data/usage.sqlite3` and the research store with `docker cp ui/research.sqlite3 chat-with-books-session:/data/research.sqlite3` (no restart needed — the sheet opens each DB per request). The container healthcheck is the local `/livez`; the sheet's `/health` still proxies to Cognee and stays the stack-level signal. Both runs serve `http://localhost:8765` — stop the host sheet before bringing the container up, one process per port.

### Phone gate

The sheet identifies a Customer by a phone number (`#phone` on the form; `inputmode="tel"`, remembered in `localStorage`). The number rides to `ui/serve.py` in an `X-Session-Phone` header on the ask (`/api/v1/recall`), the picker (`/quote-selection`), the phase-2 composer (`/quoted-answer`), and Research Mode (`/research/message`, whose `/research/turn` poll uses it to match the turn's phone) — the proxy never forwards it to Cognee. Persian/Arabic-Indic digits are normalized; anything that is not 10–13 digits is rejected with 400. Each number gets **five chats a day** (server-local day, counted in `ui/usage.sqlite3`): a chat is one ask — phase 1 records it and answers 429 when the day's five are spent; phases 2 and 3 belong to that chat, so they need a phone with at least one chat today and neither count nor check the limit themselves (the fifth chat's own Quoted answer and research conversation must pass). Honor-system — no SMS verification; the gate stops casual credit-burn, not a determined caller.

The sheet asks recall() with `stream: true`. `delta` frames are not painted — the streamed prose is no longer the displayed first answer (the Quote selection is, issue #28) — but they still drive the TTFT readout, and `final` is the only authoritative render. `reset` puts the generating status back after an LLM retry. An `error` frame is not terminal: the sheet keeps reading and prefers `final`. When the reply carries no Evidence pool — and whenever the Quote selection's prose fallback lands — the prose still renders as markdown, headings, bold, bullets; literal `#`/`**` characters never show. `ui/serve.py` relays `text/event-stream` unbuffered (HTTP/1.0, connection-close delimited). «نخستین توکن» is TTFT: submit to the first token's arrival — a token counts on arrival, the preview it used to paint is gone; with no deltas it falls back to `final`'s arrival.

### Three phases, three sections (PM brief, 2026-09-11)

One ask runs the whole pipeline, and each phase generates into its own section with a distinct separation and tabs to switch between: **پاسخ اول** (phase 1, the Quote selection — ten verbatim sentences, guarded 4–12; the streamed prose is not displayed), **پاسخ استنادی** (phase 2, the Quoted answer), and **حالت پژوهش** (phase 3, Research Mode — a guided research conversation seeded by the same question and its Evidence pool). The tab being generated carries a pulsing dot, a line under the tabs names it («در حال تولید: پاسخ استنادی…»), and each of phases 2 and 3 carries a timer chip that ticks while it runs and freezes at its completion time. A phase's section is brought forward when the phase lands — phase 1's own tab keeps the Quote selection with the Evidence pool visible-collapsed beneath it (the prose stays unseen and only feeds the Quoted answer), the guarded document lands in phase 2's, and the research replies land in phase 3's transcript under their closing «منابع» list. A new ask owns the sheet: it aborts any in-flight phase 2 of the previous one (AbortController plus the run counter), stops the research poll loop, and resets all three sections — the in-flight turn itself is aborted server-side and its session closed by this ask's own `recall` POST (see Research Mode below). The whole-pipeline elapsed clock stops when phase 2 settles — the research turns are timed by phase 3's own chip, running while a turn is live.

Phase 3 is Research Mode (ADR 0008), a chat workflow — no ask auto-starts it: its input box arms once the first answer exists, and the operator's first message creates the research session, seeded with the ask's question and its phase-1 Evidence pool as the founding goal and evidence. Each message POSTs to `ui/serve.py`'s `/research/message` (later calls carry only the text plus the `session_id`), which answers `202 {"turn_id", "session_id"}` immediately — the turn runs server-side as a registry job, not a held request, so a multi-minute evidence gather is normal and nothing blocks. The sheet stores the identities in `sessionStorage` and polls `/research/turn?turn=...` on a chained 2-second timeout, showing the turn's latest Farsi progress event; on `done` it renders the reply blocks (headings, quoted paragraphs, the engine's own notes, and the server-built «منابع» list) plus the next-move chips, on `failed`/`aborted`/`404` it lands the settled Farsi message, and a busy `429` shows the server's Farsi detail. A browser refresh reconnects to an in-flight turn through the stored identity. The gate is phase 2's shape exactly: research belongs to the chat phase 1 recorded, so it needs a phone with at least one chat today and neither counts nor checks the limit itself. The recorded Next-tier COT relay (`/next-tier-recall`) is not called by the sheet — it stays live server-side as the Session operator's probe of the second service (see Research Mode below).

Phase 2 writes the **Quoted answer** into its own tab: a document the composer writes as paragraphs that each interleave AI-written Farsi with verbatim Book sentences — one unit of AI text, embedded quote, and the paragraph's cited pages at its end (`docs/example.txt` is the visual parity target; PM format call, 2026-09-10) — the quotes taken **verbatim from the Book's Evidence passages** for the same question (ADR-0003). The sheet parses each Evidence bullet into locator + quoted passage and POSTs them with the question and the streamed answer to `ui/serve.py`'s `/quoted-answer`, which makes two sequential `glm-5.3-flash` calls on the Z.AI coding endpoint (`LLM_API_KEY` from the host env; never shipped to the browser), each with its own 240 s timeout, an explicit output ceiling (`max_tokens` 16384, pinned in source — the unpinned endpoint default ran a long document out of room mid-write, 2026-09-10, and reasoning tokens count inside the ceiling), and the endpoint's default temperature: a **planner** call with thinking enabled outlines the document — section headings, each paragraph's point, which passages to weave, where one paragraph weaves several passages — and a **writer** call with thinking disabled follows that plan to write the blocks: `heading`, `paragraph` (a `parts` list of AI text runs and quote parts). The planner plans from the question and passages alone — the draft answer is held back from it — and keeps the plan under 150 words (PM call, 2026-09-10, after live phase 2 measured ~295 s against the estimate: reasoning time scales with the brief). Reasoning is on only for planning (document structure, cross-passage weaving) and off for writing, so copied sentences survive the verbatim guard; measured 2026-09-10, reasoning cost ~84 s and writing ~17 s, so phase 2 was estimated at roughly 100 s. If the planner fails, times out, or returns nothing usable, the writer still runs without the plan — the single-call shape — so planning never breaks the fallback. A verbatim guard drops every quote sentence whose normalized letter stream does not occur in its claimed passage (PDF text-layer `\b` noise, ZWNJ, kashida, and Arabic ي/ك variants collapse before comparing), so nothing paraphrased is shown as quoted; a failed sentence drops alone and its paragraph survives. Every paragraph must hold at least one surviving quote and some AI text (no pure-AI, no bare-quote paragraphs), and a paragraph may weave quotes from several passages. Each quote sentence carries a resting clay highlight and is focusable — hover or keyboard focus shows a Farsi tooltip (Book title + that passage's first page; a passage without page markers cites the Book alone, never an invented page) — and the paragraph ends with the exact chunk-page range of every passage it quoted, in order («صفحات 740 تا 745»; the first-page-only end label lasted one smoke before the PM reversed it, 2026-09-10 — the tooltip keeps the first page). The Evidence pool — the «استناد» heading and its list — stays in phase 1's own tab, visible but collapsed («همۀ نقل‌قول‌های بازیابی‌شده») under the Quote selection since issue #28: it remains inspectable, and it stays the exact payload the Quoted answer consumes; a new ask collapses it again. While the composer runs, a pulsing «در حال نوشتن پاسخ استنادی…» status marks phase 2 in its own section, and the elapsed clock keeps counting until the document lands or the fallback settles — the timer times the whole pipeline, not just the stream (PM call, 2026-09-10). The writer is asked for at least eight quote paragraphs when the passages support them (PM call, 2026-09-10, raised from five the same night) — never inventing a quote to reach the count. The guarded document lands in phase 2's tab only when it holds at least two quoting paragraphs, or one plus a heading; if the composer fails, times out, or misses that threshold, nothing lands there and phase 1's answer stays — the Quote selection, or the streamed prose where the picker fell back — the sheet is never left empty. This runs strictly after the streamed answer: TTFT, streaming, the `Evidence:` contract, and the model pins are untouched (AC contract of #22).

A reply the output ceiling cuts (`finish_reason` `"length"`) used to lose the whole Quoted answer: the JSON died mid-array, never parsed, and the sheet fell back. Since 2026-09-11 the complete block prefix is salvaged (a `raw_decode` walk of the blocks array) and ONE continuation call — thinking disabled, same ceiling and timeout — reads the salvaged blocks and writes only what follows them, same shape and rules; the merged document runs the same verbatim guard. If the continuation is cut too (or fails), the guarded prefix still lands, the response carries `"truncated": true`, and the section says the tail may be unfinished. One continuation only — latency stays bounded.

### Round two (ADR-0010): reliability, the widen, citation landing, Book selection

Five recorded frictions, five fixes. **Reliability**: the phase-2 composer retries the writer ONCE (same plan, no planner re-run) when the guarded document misses the swap threshold or the call failed — a timeout, an empty reasoning reply, or a paraphrasing writer no longer lands «پاسخ استنادی آماده نشد» without recourse. **No empty sections**: the guard prunes a heading whose section kept no surviving paragraph (`prune_empty_sections`), and the swap threshold reads the pruned document — a bare heading with no body never renders. **The widen**: a «جست‌وجوی بیشتر» chip inside phase 1's collapsed pool POSTs `/recall-more` — one broaden call reasons out at most two short Farsi facet queries for the pool's not-yet-covered ground, each runs once through the pinned `HYBRID_COMPLETION` searcher on the next tier, and only the pool's NEW passages ride back (`{"sources": []}` is the honest no-joy shape); the sheet merges them, re-picks the Quote selection, and re-runs phase 2 over the merged pool. Gated like phase 2, never counts a chat. **Citation landing**: clicking a «منابع» reference line now locates the passage — quote spans register their text under their locator and the click looks it up — and the labeled-range fallback tries the whole chunk range (capped at nine pages), not just its first three; a quote on page five of a five-page chunk lands on page five with the highlight painted. **Book selection**: two pill toggles above the question (both on; the last one refuses to go off) choose which Books the ask searches — the recall proxy validates the body (`query` required, `datasets` intersected with the Book set, resolved list in the set's order, missing means both) and the selection rides into the research session, whose gathers and recalls search just those Books. The UI is a convenience; the server is the contract.

### Round three (ADR-0011): work over chart editing

The recorded planning loop — rewrite → approve → rewrite — is broken at its root. **Chart mode vs work mode**: only an exploration turn may park a research-question or scope proposal; an investigation turn folds its suggestions quietly. An explicit command («شواهد را گردآوری کن» and every chip) EXECUTES even while a proposal waits — the parked decision survives for the next free turn. A decided proposal starts a two-turn cooldown of its kind, and a decided text never re-proposes. **Citation-first first answer**: a stream without an Evidence block triggers ONE pinned reference-on search over the picked Book (`POST /evidence-fallback`) before the sheet concedes — the first answer is the Quote selection whenever the Books hold anything; the honest «استنادی از کتاب‌ها پیدا نشد» only when they hold nothing. **True pages**: `ui/page_resolver.py` indexes the Books' per-page text and the guard's labels resolve each kept quote's actual page (the recorded drift put every sampled passage at label−1); failure keeps the estimate, never an invented page. **The single-Book pick**: the entry chips are a radio pick — one Book per investigation, none by default, the ask disabled until chosen, persisted across refreshes. **The chat survives refresh**: `/research/messages` re-feeds the transcript and the map on reconnect.

## First answer

A Session operator asks a Farsi question against the ingested Book. First answer is Cognee `recall()` with `HYBRID_COMPLETION`. It is not Next-tier search. Pin `searchType`. Do not pass `null` (that auto-routes and can pick `GRAPH_COMPLETION_COT`). Cognee's HTTP `includeReferences` default is false. Still pass `true`. Citation is Cognee's `Evidence:` block (Book identity plus a quoted passage). Compose starts Cognee through `enable_farsi_evidence.py` so that overlap keeps Farsi terms, not only Latin `[a-z0-9]`; the same patch widens the snippet window to 600 chars (Cognee default: 160) so quoted passages hold complete sentences for the Quoted answer's verbatim guard. Do not invent a citation formatter. Do not treat CHUNKS as the product Citation. The snippet is the short summary. Do not add a second précis. A new question starts a new first answer, not a research session. Omit `sessionId` on this path.

This path streams: pass `stream: true`. Deltas never contain the `Evidence:` block, and since issue #28 they are no longer painted — they only drive the TTFT readout («نخستین توکن» measures submit to the first token's arrival; with no deltas it falls back to `final`'s arrival); the `final` frame carries the same JSON array as the non-streaming reply, and citation splitting runs on `final`'s `[0].text`. Token deltas need `LLM_ANSWER_STREAMING: "true"` in compose (Cognee env). With the flag off the stream still works with zero deltas.

Since issue #28 (ADR 0006) the rendered first answer is the **Quote selection**, not the streamed prose: with an Evidence pool present, the sheet POSTs the pool exactly as it parsed it — the `{"reference", "passage"}` pairs — to `ui/serve.py`'s `/quote-selection`, which makes EXACTLY ONE `glm-5.3-flash` call on the Z.AI coding endpoint (`LLM_API_KEY` from the host env; the model is pinned in source like every pin, never env), with thinking disabled — copy-matching, not reasoning, the phase-2 writer's measured rationale — the same `max_tokens` 16384 output ceiling, and the endpoint's default temperature. The picker is asked for the Farsi sentences that together best answer the question — aim for ten — each a complete sentence copied VERBATIM from exactly one numbered passage. The reply runs the existing verbatim letter-stream guard: a sentence whose letter stream is not inside its claimed passage, or that claims the wrong index, drops — never shown as quoted. Survivors cap at twelve; fewer than four means the picker missed the floor and the reply is empty. The picker's 200 reply carries the pool's size as `pool_size` beside the selections — recorded here so the coming benchmark re-record can correlate pool size with wall-clock. Each surviving sentence renders with its own Citation tooltip — Book identity plus that passage's first page — and its resting page-range label. ## Research Mode

In the same Session, on the same question, the operator opens **حالت پژوهش** — Research Mode (ADR 0008, the Research Wayfinder): a guided, evidence-grounded research conversation that replaces the old one-shot Deep dive. A new question is a new first answer and a new research session. Slow is allowed here (an evidence gather runs minutes by design); it must not steal the first-answer path.

Two layers run at once (per the Wayfinder design). The **conversation layer** keeps normal chat freedom: every message is first classified by ONE `glm-5.3-flash` intent call (thinking on — the reasoning pass) into casual / concept-learning / source-lookup / research-exploration / active-research / drafting / closing-review / evidence-audit / map-keeper (T12), and a casual or lookup message is answered normally — one searcher over the message and one guarded writer pass, no research formalism. A malformed classify reply degrades to the conversational path, never crashes. The **research state layer** maintains a persistent state behind the chat: the versioned research question, scope, sub-questions, an evidence ledger, a claim ledger, gaps, decisions, and the phase. Research behavior strengthens with intent, never applies uniformly. Fixed Farsi chip commands map deterministically (no classification luck): «شواهد بیشتری از کتاب‌ها پیدا کن» (gather), «شواهد را تحلیل و جمع‌بندی کن» (synthesize), «خلاصۀ پژوهش را بنویس» (the Brief), «ادعاها و استنادها را بازبینی کن» (audit), «بازنویسی بخش‌های ناکام خلاصه» (the Closing review's revise, T9), «نقشه را مرتب کن» (the map keeper's survey, T12).

The **journey layer** (ADR-0009, adapted from the Wayfinder skill) turns those pieces into a guided journey instead of an operations menu. A **stage machine** — orientation (name the destination), mapping (survey the ground breadth-first), investigating, synthesizing, drafting — moves ONLY by code on observable state; the model proposes content, never moves a stage. In the early stages the reply can be a **guided question**: ONE sharp question authored per turn (thinking on), two to four short option chips, always a skip chip («فعلاً همین کافی است؛ ادامه بده») — the agent asks and NEVER answers its own question. The user's answer lands in the **decisions** index, and the orientation answer names the **destination**: what the user wants to walk away with. Guided questions are process speech — no Book facts, so nothing for the verbatim guard to check; anything grounded derives from the concepts the investigation has actually seen. Open questions are **named** («شهود و ساحت») and worked individually — «شواهدِ «شهود و ساحت» را پیدا کن» resolves server-side by pattern, no classification luck. The **fog** («هنوز نامشخص») holds coming-but-not-yet-sharp questions that graduate into open questions as the journey advances; out-of-scope items never graduate. Every material operation's reply opens with a short **narration** note — what changed on the map and what is next, qualitative only (never numbers, never Book claims; the server's own fact line carries the numbers). The sheet renders the whole route as the **research map** («نقشۀ پژوهش») — the persistent side rail beside the chat, always visible without scrolling (T10, GitLab #11), named from CONTEXT.md's approved plain-Persian table — led by a five-stage journey strip: destination, question with version count, the frontier («در حال پرداختن»), the named open questions with statuses, decisions, fog, out of scope, and the counts. Checkpoint chips carry short labels — «می‌پذیرم» / «رد می‌کنم» — with the proposal text in the note above, never inside the chip. A V0.1 session in the store loads under a pure shape upgrade: the old phase word derives the stage, unnamed sub-questions gain names, the map defaults fill in.

The **checkpoint rule** is the safety heart: a research-question or scope change proposed by the classifier NEVER applies itself — it lands as a pending proposal the user accepts or rejects through `/research/decide` («می‌پذیرم» / «رد می‌کنم» chips), and an accepted question change appends a version with its reason (v1 stays intact underneath — provenance, never silent replacement). The **Brief plan** (ADR-0012) is a third proposal kind in the same decide flow — sections mapped to their named open questions and the claims that will support them, parked only on an exploration turn, damped by its own two-turn cooldown, accepted append-only into a versioned plan ledger — and once plans are required, the Brief refuses to write without an accepted plan. The work chips (gather, synthesize, brief) are never hidden behind a waiting proposal: the decision pair leads the row and the moves stay beside it, because deciding must not block working.

The **state caps** (T12, GitLab #13) keep a long session honest and bounded: the working ledgers — the evidence ledger, the claim ledger, the gaps, the decisions index — keep their NEWEST entries past hard caps (`RESEARCH_MAX_EVIDENCE`/`RESEARCH_MAX_CLAIMS`/`RESEARCH_MAX_GAPS`/`RESEARCH_MAX_DECISIONS`, pinned in source like every cap), so the pool a synthesis or a Brief section reads — it is the ledger itself — can never outgrow its bound and the prompts stay bounded however long the investigation runs. The map's own rows never trim silently: the **map keeper** (نقشه‌بان, T12) is the survey skill — pure code, no upstream call — that reads the map and proposes its cleanups as ONE pending decision through the standing decide flow, damped by the usual two-turn cooldown: duplicate open questions (the older of two on one topic), stale fog (a fog note a question's topic already took over), and safe trims (finished questions beyond the map's readability keep — their evidence, claims, and gaps stay in the ledgers). The proposal names every row it would remove; accepting applies exactly the named rows and records the cleanup in the decisions index, rejecting records the refusal — and an exact cleanup already decided never re-parks. Nothing is deleted silently and the provenance stays append-only.

A research turn executes at most ONE bounded operation, chosen deterministically when the user does not force one: **gather** — evidence until the floor (six passages) or the pending sub-questions are covered — then **synthesize** (the first analysis), then the **Brief**. The gather is the old dive's fan-out, unchanged in its caps: up to six parallel searchers on the second Cognee service (`NEXT_TIER_URL`, default port `8001`), each pinning `HYBRID_COMPLETION` over `["tarhe-kolli", "70143-336"]` with `includeReferences: true` on its own 600 s leash, Evidence passages parsed server-side and merged into the ledger (deduplicated on the guard's normalized letter stream — the same passage re-parsed by a different searcher never counts twice). Sub-questions that come back **quote-starved** (their searcher parsed fewer than two passages) get exactly **one gap round**; **at most two retrieval rounds** total — the lock that keeps a turn from growing an unbounded agentic loop. A sub-question still starved becomes an honest **gap entry** — «کتاب‌ها برای این بخش شواهد کافی ندارند؛ این بخش را نمی‌توان از همین کتاب‌ها اثبات کرد» — never a hallucinated fill. The gather's reply is server-composed notes (counts and gaps), so a gather makes no claim a guard would have to check. **Synthesize** is one guarded writer pass over the accumulated ledger (thinking disabled — copied sentences must survive the verbatim guard, the phase-2 writer's measured rationale); each kept quoting paragraph records a **claim** whose status is code-derived, never model-claimed: one distinct passage is `direct_support`, more is `supported_synthesis`. The **Brief** is assembled section by section (T8, GitLab #9) against the accepted plan's Section contracts: acceptance derives each section's contract (its claims filtered to the ledger, the question it answers, the scope lines it must not cross), each section is written as ONE bounded writer op over the research state — never the chat transcript — with the guard and exactly one retry, and a section the Books cannot feed falls back honestly (a diagnosed, ledgered gap note under the plan's own heading), so the finished Brief matches the plan the operator accepted and cannot drift from it; the Brief refuses to run without recorded claims first and, now that plans are required, without an accepted plan second. The finished Brief then faces the **Closing review** (T9, GitLab #10) before it is done — the assembly's sections stand in the state (`brief_document`), and the review runs on two axes in order: pure code first traces every section to its contract (the pinned claims carried by quoted evidence, no scope line crossed in the section's own words, an honest gap read as starvation not failure), and only then runs the ONE **destination-judgment** call, asking whether the document delivers the destination or honestly states what the Books cannot establish. The verdict lands in the same reply with the accept/revise chips: accepting marks the Brief reviewed through the standing decide flow; the revise chip («بازنویسی بخش‌های ناکام خلاصه») sends its own command and reruns ONLY the flagged sections — the passing sections keep their written paragraphs — and the review then faces the reassembled document again. A judgment call the budget refuses or that answers unusably lands `unjudged` with a diagnosis recorded: the code findings and the chips stand alone, never a silence. A judgment that fails the destination with no flagged section flags every written section, so the revise set is always explicit. The **audit** is pure code: the claim ledger re-reported with its statuses and the gaps, no LLM call — the audit inspects the claim ledger, not the Brief (CONTEXT.md keeps the two reviews apart; the review is بازبین, the audit بازبینِ دفتر ادعاها). Every reply that states a Book fact runs the same verbatim guard as phases 2 and 3, the references list is built server-side from the passages actually quoted (never the model's job), and a pool the guard cannot feed lands the honest Farsi note — «نقل‌قولی از کتاب‌ها برای این پیام پیدا نشد.»

A turn is a job in an in-process registry (the dive's shape, issue #26): `POST /research/message` answers `202 {"turn_id", "session_id"}`, the sheet polls `/research/turn?turn=...` for `{"state", "events", "elapsed"}` — `classifying` → `planning`/`searching`/`writing`/`reviewing` → `done`, each transition appending a Farsi progress event — and a `done` poll carries `{"reply", "suggestions", "research_state"}`; `failed` carries a short Farsi detail, an unknown id answers `404`. `GET /research/state?session=...` feeds the sheet's «نقشۀ پژوهش» research map (destination, question with version count, the frontier, the named open questions, decisions, fog, out of scope, and the counts) together with the live chip set (`suggestions`) — a browser refresh re-renders the map AND the chips, so a live guided question's options and its skip survive the reload (T10, GitLab #11). The registry is stdlib-only (a dict, a lock, threads): at most **one in-flight turn per phone** and **three globally**; a start beyond a cap answers 429 with a friendly Farsi busy detail and is never queued. A session's soft cost bound: at forty turns every reply suggests writing the Brief — a suggestion, never a refusal. The **session itself persists in SQLite** (`ui/research.sqlite3`, the quotas.py pattern — its own file so a patched quota DB and a patched research DB never share a test): a server restart empties only the in-flight-turn registry (a poll for a pre-restart turn id answers 404 — the recorded failure surface, never a hang) while the session, its state, and its transcript reload from the store and the conversation continues. A browser refresh reconnects to an in-flight turn through the `sessionStorage` identity (the earlier transcript is not re-fetched in V0.1 — the session continues server-side). A **new ask aborts** the asker's in-flight turn — cooperatively, after the ask gate records the chat, the same `recall` POST marks the phone's non-terminal turn `aborted` and closes its session (a later message answers the Farsi closed detail) — and another phone's research is never touched.

The searchers pin `HYBRID_COMPLETION` (amended 2026-09-12, the live smoke of ticket #25): the once-pinned `GRAPH_COMPLETION` renders no `Evidence:` block on the second service — its references arrive as graph-node metadata with no verbatim passage text — so the quote pool is empty by construction, every sub-question starves through both rounds, and the gather lands its honest gap; the recorded real reply is the negative fixture `tests/fixtures/recall-graph-completion-8001.json` (locked to parse to zero passages), and the same question over `HYBRID_COMPLETION` on the same service is the positive fixture (`recall-hybrid-completion-8001.json`): the `Evidence:` contract with locators carrying Book identity and pages, exactly what the verbatim guard quotes from. The searchers' search type is not `FEELING_LUCKY`, not `AGENTIC_COMPLETION` (it requires exactly one dataset; the Book set is two), and no longer `GRAPH_COMPLETION` (recorded unusable for the pool). If hand-planned sub-questions disappoint, the recorded fallback is `GRAPH_COMPLETION_DECOMPOSITION` — switch only after recording that choice; the 2026-09-12 failure was a searcher-reply-shape disappointment, not a planning one.

Beyond the fan-out, every way of searching the picked Book is a named **Tool** in `ui/dive.py`'s registry (ADR-0012, T4), and the gather skill row declares the names it may use: `hybrid` (`HYBRID_COMPLETION`, the 600 s dive leash, parses `Evidence:` blocks to citable passages), `chunks` (`CHUNKS`, a fast 120 s fuse — no LLM round — the verbatim chunk text with its reference built server-side, pages read from the text layer's `Page N:` markers and the Book identity from the item's dataset name or the pick), `graph` (`GRAPH_COMPLETION`, 600 s), `decomposition` (`GRAPH_COMPLETION_DECOMPOSITION`, 600 s), `context_extension` (`GRAPH_COMPLETION_CONTEXT_EXTENSION`, 600 s), and `summaries` (`SUMMARIES`, 120 s). The result shapes are the registry's own contract: **passages** (hybrid, chunks) may enter the evidence ledger and be quoted; **concepts** (the graph family — the node labels of the recorded negative fixture, its text being model-written synthesis) and **notes** (summaries — cognee's words, not the Book's) never do. A frontier-wide gather rides one bounded **graph hop**: one graph completion over the gather's seed, its top labels steering at most two further citable hybrid searches (`seed — label`), the hop's ledger entries carrying `via: "graph"` and the labels growing the map's concept row — the angles one search mode misses, without a model-written sentence ever posing as a Book quote. A targeted chip («شواهدِ «نام» را پیدا کن») gathers only its named question and runs no hop. Every Tool enforces the session's picked Book — an empty pick raises, never the whole-set default (that stays the ask path's rule) — and the unsupported modes stay out by construction: the registry holds no `CYPHER`, `NATURAL_LANGUAGE`, `AGENTIC_COMPLETION`, `FEELING_LUCKY`, or `GRAPH_COMPLETION_COT` (the last remains the operator relay probe only), and an unregistered name is a refused call recorded as a diagnosis, never a silent empty pool.

The searchers run on the second Cognee service (`cognee-next-tier`, port `8001`). Both tiers run `glm-5.3-flash` since 2026-09-13 (operator call — deep-study latency was the pain); before that the tiers differed since 2026-09-09 — `glm-5.3-flash` first answers, `glm-5.3` here. They stay separate services so a multi-minute research gather on `8001` never blocks the first-answer path on `8000`: Cognee's per-stage `LLM_QUERY_MODEL` override cannot draw that line — it hits every search completion, first answer included — and one service cannot serve both tiers independently. Both read the same Postgres memory.

The recorded Next-tier COT relay (ADR 0005) — `ui/serve.py`'s `/next-tier-recall` — stays live server-side as the operator probe of the second service; the sheet no longer calls it. This probe (`GRAPH_COMPLETION_COT`, default `max_iter=4`) remains the live engine of that relay, which waits on its own leash — `NEXT_TIER_TIMEOUT`, default `1200` s, tunable from the compose environment: a COT search runs four chain-of-thought rounds and can pass ten minutes (live logs, 2026-09-11), and the shared 600 s proxy leash once gave up on a search the second service had already finished:

```powershell
curl.exe -sS -X POST http://localhost:8001/api/v1/recall -H "Content-Type: application/json" --data-raw '{"searchType":"GRAPH_COMPLETION_COT","query":"اندیشه اسلامی در قرآن چه طرحی دارد؟","datasets":["tarhe-kolli","70143-336"],"includeReferences":true}'
```

Same question as the first answer. Do not stream this probe; the operator waits for the JSON. Citations may still appear; they follow the first-answer `Evidence:` contract. Pytest locks this recorded contract; a green suite does not mean the dive — or the relay — returned a synthesis.

## VPS deploy

The public deployment is one Ubuntu VPS running the full stack behind **https://booksai.rayesh-team.ir**: the compose services (Postgres, Cognee `8000`, next-tier `8001`, all loopback-bound) plus the Session sheet under a systemd unit `cwb-session.service` (`User=ubuntu`, `EnvironmentFile` pointing at the repo's `.env` for `LLM_API_KEY`, `SESSION_UI_HOST=127.0.0.1`, `SESSION_UI_PORT=8765`). The sheet can also run in compose under the `session` profile (see Session UI) — but on the VPS the profile's published `0.0.0.0:8765` and the unit's `127.0.0.1:8765` are one port: retire the systemd unit (`sudo systemctl disable --now cwb-session`) before ever bringing the profile up there, or the container's bind fails. Nothing binds a public port anymore (2026-09-10): nginx fronts the domain — `/etc/nginx/sites-available/booksai.rayesh-team.ir`, proxying to `127.0.0.1:8765` with `proxy_buffering off` and read/send timeouts that sit at or above the sheet's `NEXT_TIER_TIMEOUT` (1200 s — the 600 s pair predates the 2026-09-11 leash fix and would cut a long Next-tier search at the front after the sheet had stopped cutting it), because the SSE stream, the ~140 s `/quoted-answer` POST, and the `/next-tier-recall` relay all ride it (the long riders since #26 — the `/research/message` POST is now a fast turn start and the sheet's status polls are short; the multi-minute gather runs server-side behind the turn registry) — and the Let's Encrypt cert (`certbot --nginx`, auto-renews) terminates TLS on the VPS. The Cloudflare DNS record is **DNS-only (grey cloud)**, pointing straight at the VPS: TLS is the origin's job and no Cloudflare proxy sits in the path. If that record is ever flipped to proxied (orange cloud), Cloudflare's ~100 s origin timeout will cut the silent `/quoted-answer` POST with a 524 — phase 2 would need to stream heartbeat bytes before its JSON, a seam that does not exist today. The VPS shares the host with unrelated projects (`mitgrat-*`, `mcdc-web`), so before binding anything check `ss -tlnp` — every service keeps its unique port and never assumes the repo defaults are free.

Deploy is tarball-shaped (the VPS copy is not a git checkout): tar the tree locally excluding `.git`, `.env`, the Book PDF and caches, `pscp`/`scp` it over, swap the tree (keep the remote `.env`), then `sudo systemctl restart cwb-session`. If `docker/enable_farsi_evidence.py` changed, restart the Cognee container too (`docker restart chat-with-books-cognee`) — the snippet window applies at search time, so no re-ingest is needed; the bind mount re-reads the file on container start.

Two VPS-only compose facts, recorded 2026-09-12 when next-tier came up there: the stack's compose project is **`chat-withbooks`** (no dashes — the identity the running containers and the data volumes `chat-withbooks_postgres_data` / `chat-withbooks_cognee_*` carry, where the ingested memory lives), so the stack comes up with `docker compose -p chat-withbooks up -d` — a bare `up` in the swapped tree would invent a `chat-with-books` project and collide on container names. And the repo's compose publishes `0.0.0.0` for local dev, while the VPS runs every host port loopback-bound: after a tree swap, prefix the compose's host ports with `127.0.0.1:` before `up` (Docker publishes bypass ufw — an unprefixed `8001` would face the internet). The tarball swap also carries `ui/usage.sqlite3`, `ui/research.sqlite3`, and `.env` over from the previous tree (quota counts, research sessions, and keys), and `cognee-next-tier` is created on first `up` — Research Mode's searchers need it on `127.0.0.1:8001`.

The embedder is frozen into the ingested data: compose interpolates `EMBEDDING_MODEL`/`EMBEDDING_DIMENSIONS` with the ADR 0004 default (`text-embedding-3-large`/3072), so a stack whose pgvector tables were ingested before ADR 0004 (`text-embedding-3-small`/1536) must pin small/1536 in the VPS `.env` until re-ingested. 2026-09-12: a `docker compose up -d` recreated the containers with the large/3072 embedder over small/1536 tables, and every search errored (`expected 1536 dimensions, not 3072`) while the health probes stayed green — post-deploy verification therefore includes one real `/api/v1/recall` search, not just health probes.

The Book datasets are ingested once (`DATASET_PROCESSING_COMPLETED` in `/api/v1/datasets/status`); re-ingest is not part of a code deploy.
