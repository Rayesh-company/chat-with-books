Amended 2026-09-12 (gap round landed, issue #27): the bounded second retrieval ships. A section is quote-starved when its round-1 searcher parsed fewer than two Evidence passages (`DIVE_STARVED_PASSAGES = 2` — a section with fewer than two cannot weave a quoted paragraph pair; the count is the searcher's own parsed pool, not the post-synthesizer guard). Starved sections re-search exactly once, in parallel, only the starved sub-questions, their fresh passages appending to the deduplicated pool so passage indices stay stable; the round is announced in a Farsi progress event while the state remains `searching`. Two locks bound the whole topology: at most six searchers per round (the Planner cap) and at most two retrieval rounds (`DIVE_MAX_RETRIEVAL_ROUNDS = 2`) — the bound that keeps the dive from growing an unbounded agentic loop; a pathological always-starved upstream runs exactly two rounds and then lands `done` or the no-evidence `failed`, never a third.

## Considered options

- Mastra as the agent harness. Rejected: TypeScript/Node-only with no Python SDK — it would add a Node sidecar to the Python/Postgres compose stack purely for primitives stdlib threads already provide.
- The OpenAI Python SDK as the orchestration layer. Rejected: the repo is deliberately zero-runtime-dependency (bare `python:3.12-slim` image), the stdlib composer already runs the same call shape, and `AsyncOpenAI` across `asyncio.gather` batches carries a known connection-reuse sharp edge (openai-python#1059). Revisit only with the durability upgrade.
- Redis, or Redis + BullMQ, for the job registry. Rejected: BullMQ is a Node library (same sidecar objection as Mastra); a broker is unwarranted at ≤3 concurrent jobs on one process; Postgres job rows without durable execution cannot resume a dead dive — they would only be a tombstone the sheet's failed status already conveys.
- Cognee's own modes for the whole dive. Partial: `GRAPH_COMPLETION_DECOMPOSITION` (splits 1–5 subqueries, retrieves per subquery, synthesizes, ~60 s) is the recorded fallback if hand-planned sub-questions disappoint; `AGENTIC_COMPLETION` stays rejected, now on a second ground — it requires exactly one dataset and the Book set is two. No Cognee completion type returns anything but a single answer string, so the guarded multi-page essay contract lives in `serve.py` regardless.
- Keeping the streamed prose as the phase-1 answer with the selection above it. Rejected: the Quote selection is the first answer (CONTEXT.md); the prose would either compete with it or be generated unseen.
